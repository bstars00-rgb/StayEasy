# OhmySelect QA Checklist

작성일: 2026-06-07

## 1. 핵심 사용자 흐름

- 게스트가 홈, 탐색, 상세, 비교, 추천 퀴즈를 볼 수 있다.
- 게스트가 저장/구매/예약/선물을 누르면 로그인 안내가 뜬다.
- 로그인 완료 후 사용자가 누르던 액션이 이어진다.
- 무료 멤버십 가입 시 지갑에 즉시 지급된다.
- 유료 멤버십 구매 신청 시 주문이 `requested`로 생성된다.
- 주문이 `activated`가 되면 지갑에 멤버십과 바우처가 지급된다.
- 바우처 예약 요청 시 `requested` 예약이 생성되고 available 수량이 줄어든다.
- 예약이 `completed`가 되면 used 수량이 증가한다.
- 예약이 `cancelled`가 되면 hold가 해제된다.
- 선물 가능한 바우처만 transfer 생성이 가능하다.

## 2. 바우처 재고

- `available = quantity - used - held - transferred`가 맞다.
- requested/confirmed 예약은 held로 계산된다.
- completed 예약은 used로 계산된다.
- cancelled 예약은 재고에 영향을 주지 않는다.
- 마지막 1장 바우처를 동시에 두 번 예약할 수 없다.
- 마지막 1장 바우처를 예약과 선물로 동시에 사용할 수 없다.
- 수량을 초과해 completed 처리할 수 없다.

## 3. 주문/정산

- 결제 금액은 클라이언트가 아니라 서버가 계산한다.
- `salePrice`가 정가보다 낮을 때만 적용된다.
- `commissionAmount = paidAmount * commissionRate` 반올림이 일관된다.
- `activated` 주문만 정산에 포함된다.
- 취소 주문은 정산에서 제외된다.
- 이미 활성화된 주문을 다시 활성화해도 지갑이 중복 지급되지 않는다.
- 일반 사용자가 주문을 임의로 `paid` 또는 `activated` 처리할 수 없어야 한다.

## 4. 예약

- 성인 수는 1명 이상이어야 한다.
- 예약 날짜는 필수여야 한다.
- 소아 수와 `childAges` 개수가 일치해야 한다.
- 소아 나이는 허용 범위 안에서만 저장된다.
- 예약 날짜가 과거이면 거절한다.
- 호텔이 바우처 대상 호텔 목록과 맞지 않을 때 경고 또는 거절 정책이 적용된다.
- 상태 전이는 허용된 방향만 가능하다.
- 일반 사용자가 예약을 임의로 `completed` 처리할 수 없어야 한다.

## 5. 인증/계정

- Google ID token은 서버에서 검증한다.
- 다른 사용자의 지갑, 주문, 예약, 선물 기록을 조회할 수 없다.
- 로그아웃 후 보호 API 접근이 거절된다.
- refresh token 만료 시 재로그인이 필요하다.
- 계정별 데이터가 섞이지 않는다.

## 6. 다국어/지역화

- 한국어, 영어, 베트남어, 중국어, 일본어가 표시된다.
- 번역 누락 시 영어로 fallback된다.
- 날짜와 통화 포맷이 언어/통화에 맞게 표시된다.
- API 오류 메시지는 코드 기반으로 프론트에서 번역 가능하다.

## 7. Claude 프론트 연동 QA

- `VITE_API_BASE_URL`이 없을 때 기존 mock/localStorage 모드가 동작한다.
- `VITE_API_BASE_URL`이 있을 때 API mode가 동작한다.
- API 응답 지연 중 로딩 상태가 보인다.
- API 오류 시 화면이 깨지지 않는다.
- API 필드명이 문서와 다르면 테스트에서 실패한다.
- 화면 라우트와 하단 내비게이션이 유지된다.

## 8. 회귀 테스트 후보

- 무료 가입 -> 지갑 -> 예약 -> 완료
- 유료 구매 -> 인보이스 -> 결제 완료 -> 활성화 -> 지갑
- 게스트 액션 -> 로그인 -> 액션 재개
- 비교 목록 최대 3개 제한
- 바우처 상세 모달의 설명/조건/호텔 표시
- 선물 생성 후 available 감소
- 멤버십 제거 후 관련 예약/사용/선물 정리, 주문 이력 보존
